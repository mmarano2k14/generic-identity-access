# Generic Identity 1.5.0 — Repository Professionalization

**Date:** 2026-10-02  
**Scope:** repository naming, validation structure, development consumer fixtures, and source hygiene

## Purpose

Normalize the Generic Identity repository so public and internal documentation uses functional,
professional naming and the reusable Identity codebase remains consumer-neutral.

## Added

- Functional Shared Identity validation scripts named by responsibility.
- `scripts/shared-identity/verify-professional-nomenclature.ps1`.
- Functional validation manifests under `docs/shared-identity/validation-manifests/`.
- Consumer-neutral local development fixture identifiers:
  - `consumer-web`
  - `consumer-app`
  - `consumer-primary`

## Modified

- Shared Identity documentation now uses functional milestone names.
- OrganisationProfile and Organization Directory documentation now uses functional milestone names.
- Repository verification calls the renamed validation scripts.
- Development client and administration bootstrap scripts use consumer-neutral fixture identifiers.
- Test fixtures use `consumer-app` rather than a product-specific application name.
- `SOURCE_MANIFEST.sha256` was regenerated from the cleaned source tree.

## Removed

- Historical numbered milestone manifests that were no longer part of the active validation contract.
- Generated qualification and release artifacts from the source snapshot.
- Obsolete numbered validation script names.
- Consumer-product-specific local development naming.

## Runtime changes

No production authentication, authorization, RBAC, session, MFA, routing, persistence, or API semantics are changed.

## Database migrations

None.

## Breaking changes

No public Generic Identity SDK breaking change is introduced. Local development fixture identifiers and
validation-script file names change; repository-local automation must use the new functional names.

## Post-apply validation

Run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

The repository-level verification includes the permanent professional-nomenclature gate.
