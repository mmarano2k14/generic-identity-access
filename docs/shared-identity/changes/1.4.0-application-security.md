# Generic Identity 1.4.0 — Application Security Change Record

**Date:** 2026-10-01  
**Classification:** Additive public SDK and shared presentation release

## Summary

This release promotes the existing application-security backend capabilities into the categorized Generic Identity SDK and shared React/Next.js presentation surface. Existing compatibility APIs remain intact.

## Added

- `@generic-identity/contracts/application-security`;
- `@generic-identity/auth/application-security`;
- `GenericIdentityClient.applicationSecurity`;
- categorized security-model, manifest, scope-type, capability-catalog and administration-context clients;
- structured `IdentityApplicationSecurityPermissionReference` contract;
- `createApplicationSecurityPermissionReference(...)` fail-closed helper;
- reusable Application Security React pages and administration forms;
- `@generic-identity/next/application-security` re-export surface;
- source qualification for the Application Security boundary.

## Modified

- aligned Generic Identity package versions from `1.3.0` to `1.4.0`;
- live SDK feature inventory updated to mark the backend-supported Application Security surface complete;
- living SDK documentation now uses named implementation milestones instead of internal numbered delivery labels.

## Moved

None.

## Deleted

None.

## Database migrations

None.

## Runtime changes

None in the Generic Identity backend. The new SDK facade composes existing TypeScript transport clients.

## Breaking changes

None. Existing administration and compatibility surfaces remain available.

## Security impact

No authorization shortcut is introduced. Capability metadata remains non-authoritative, effective administration context remains server-derived, and TRN materialization/authorization remain server-side concerns.

## Post-apply validation

The release must preserve:

- Generic Identity contracts typecheck;
- Generic Identity auth SDK typecheck;
- application-security public subpath exports;
- aligned `1.4.0` package versions;
- no consumer-product naming in the reusable Application Security source;
- no backend endpoint, database schema or RBAC semantic changes;
- all previously qualified validation gates.
