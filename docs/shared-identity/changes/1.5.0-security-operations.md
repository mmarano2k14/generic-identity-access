# Generic Identity 1.5.0 — Security Operations Change Record

**Date:** 2026-10-07  
**Classification:** additive public SDK, reusable administration workflow, and presentation qualification

## Summary

Generic Identity `1.5.0` exposes the existing server-backed session-revocation, MFA-administration, authenticator-lifecycle, and security-audit capabilities through the categorized Security Operations SDK. The current source line also completes the reusable Next.js administration workflows required to consume those capabilities safely from a Next.js application.

## Added

- `@generic-identity/contracts/security-operations`;
- `@generic-identity/auth/security-operations`;
- categorized `security.sessions`, `security.mfa`, and `security.audit` clients;
- reusable MFA administration workspace and mutations;
- reusable Security Audit bounded query workspace and filter presentation;
- reusable Session Security evidence workspace and user/client containment mutations;
- `MfaPage`, `MfaPolicyForm`, and `AuthenticatorRevocationForm` enhancements;
- `SecurityAuditPage` and `SecurityAuditFilterForm`;
- `SessionSecurityPage`, `SessionSecurityFilterForm`, and hardened `SessionRevocationForm`;
- source and behavior qualification for the Security Operations integration boundary.

## Modified

- aligned Generic Identity package versions remain `1.5.0`;
- Security Audit now supports reusable bounded User, Tenant, Outcome, Correlation, and window filters;
- Sessions administration no longer presents consumer session context as an active-session inventory;
- session administration uses bounded audit evidence plus server-confirmed user/client revocation;
- destructive session/authenticator revocation workflows require explicit confirmation;
- public documentation distinguishes backend feature availability from live consumer qualification.

## Moved

None.

## Deleted

None.

## Database migrations

None.

## Runtime changes

No backend route or persistence semantic is changed by the shared SDK integration. Reusable workflows delegate to existing server endpoints.

## Breaking changes

None. Existing compatibility surfaces remain available.

## Security impact

- no authorization shortcut is introduced;
- no active-session state is inferred where no backend list contract exists;
- audit remains bounded and read-only;
- provider secrets and session credentials remain excluded from shared presentation contracts;
- missing enrollment endpoints remain explicitly unavailable rather than being simulated.

## Qualification status

Security Audit and Sessions reusable workflows have completed functional consumer qualification. MFA administration is implemented and source-qualified; dedicated live functional acceptance remains pending.
