Apply this ZIP as an overlay on the 0.49.0 GREEN tree.
This increment closes the planned backend/security sequence with authenticated self-service password replacement, recovery-code-backed account recovery, and credential-continuity invalidation.
Self-service password replacement revalidates the exact local session, current password, trusted route, optimistic credential version, and recent MFA when the current application MFA policy is Required.
Recovery-code account recovery accepts login identifier + recovery code + replacement password; the server resolves the single active recovery authenticator and does not require its identifier from the caller.
Successful password replacement revokes active local sessions and unrevoked OIDC refresh tokens; account recovery consumes the recovery code, replaces the password, clears lockout state, and performs both revocations in one PostgreSQL transaction.
Migration 0020_credential_security_hardening.sql expands the constrained refresh-token revocation reasons with credential_changed and account_recovery.
Run .\scripts\verify.ps1 after overlay. Do not treat 0.50.0 as GREEN until that command succeeds in the target .NET 10 environment.
After 0.50.0 is GREEN, the planned next phase is reusable administration/login/security UI and UX refinement; any verification defect remains a 0.50.x corrective patch.
